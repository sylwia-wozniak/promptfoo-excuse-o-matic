Why test prompts?

Because AI answers change

01

The same question, different answers

Models pick their words with some randomness. A prompt that worked today can fail tomorrow, with nothing changed.

02

Small edits break things

One new sentence in a prompt can fix one case and break three others. Without tests, you only find out from users.

03

Numbers beat gut feeling

Which prompt is better? Which model? An eval gives you a pass rate instead of "it looked fine when I tried it".

How promptfoo works

One config, one command

You describe prompts, models and tests in a YAML file. promptfoo sends every combination to the models, checks every answer and shows a report.

# promptfooconfig.yaml (lesson 1, shortened)
prompts:
  - |
    You are Excuse-o-Matic 3000, a friendly assistant that writes funny,
    polite excuses. Start your answer with "Sorry". Keep it to 1-2 sentences.

    Write an excuse for: {{mishap}}
providers:
  - id: ollama:chat:llama3.2:3b
tests:
  - vars:
      mishap: "being 10 minutes late for the morning standup"
    assert:
      - type: icontains
        value: sorry
      - type: javascript
        value: output.length <= 280
8 words to know

The vocabulary

Prompt

The text you send to the model. It can have {{variables}}.

Provider

The model that answers, e.g. ollama:chat:llama3.2:3b.

Test

One example input, plus the checks its answer must pass.

Variables

vars fill the blanks in the prompt. One prompt × 10 tests = 10 model calls.

Assertion

One check on an answer: contains a word, is valid JSON, a judge says "kind"…

Pass rate

How many tests passed. In CI you set a bar, e.g. "at least 80%".

Temperature

How random the answers are. 0 = the same answer every time.

Cache

promptfoo saves answers and reuses them. --no-cache asks the model again.

Start in 5 minutes

Setup

  1. Install Node.js 22.22+ and Ollama

    Get them from nodejs.org and ollama.com. Ollama runs AI models on your computer.

  2. Download a model (about 2 GB)

    ollama pull llama3.2:3b

    Some lessons also use qwen2.5:3b and gemma3:4b.

  3. Get the code

    git clone https://github.com/sylwia-wozniak/promptfoo-excuse-o-matic.git
cd promptfoo-excuse-o-matic
npm install

  4. Run lesson 1 and look at the results

    npm run lesson:1
npm run view

    One test fails on purpose, so you see what a failure looks like.

What surprised us

5 things we learned

01

Small judges say "yes" too easily

An AI judge needs its own tests. Ours missed a rude, a vague and an off-topic excuse. Lesson 6

02

Built-in checks can misfire

is-refusal treats an answer starting with "Sorry" as a refusal. Every excuse starts with "Sorry". Lesson 8

03

Temperature isn't personality

At temperature 0 Qwen still refused "skipped leg day" every time. Temperature changes randomness, not what a model prefers. Lesson 9

04

The cache can hide flakiness

Run an eval twice and the second run replays the first answers. Use --no-cache when you measure. Lesson 9

05

Always fails = a bug, not bad luck

A test that fails every run points to a problem in the test, prompt or model. Fix it before it goes into CI. Lesson 10

The big one

Run important tests several times and read the pass rate, not a single ✅.

FAQ

Questions

Do I need an API key or a paid account?

No. Every lesson runs on Ollama, on your own computer. The GitHub Actions run in lesson 10 is free for public repos.

Why are my results different from the READMEs?

AI answers are partly random, and different computers can pick different words. That's normal, and it's what lesson 9 is about. Look at pass rates, not single answers.

How long does a lesson take?

Each eval runs in about 1–2 minutes. Reading a lesson and trying its exercises takes 15–30 minutes.

My computer is slow. Can I use a smaller model?

Yes. Try ollama pull llama3.2:1b and change the provider id in the lesson's promptfooconfig.yaml. Results will be different, which is a lesson too.

Can I run it in CI?

Yes, lesson 10 has a GitHub Actions workflow. You start it by hand from the Actions tab, and it runs Ollama inside GitHub's runner.
